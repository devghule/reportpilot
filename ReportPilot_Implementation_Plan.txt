1. PROJECT ARCHITECTURE
================================================================================

WHAT EACH LAYER DOES
--------------------

NestJS Backend (/backend)
The core server. Handles all Meta API calls, OpenAI calls, token encryption,
scheduling cron jobs, Google Sheets API writes, user management, and plan gating.
Nothing sensitive happens outside this layer. The React sidebar talks to this.
Apps Script talks to this. This is the source of truth.

React + Vite Sidebar (/sidebar)
A React app bundled by Vite and served as static files from the NestJS backend
at /public/sidebar. Apps Script loads this in an iframe inside Google Sheets.
The sidebar handles all UI — login, Meta connect, template selection, import,
schedule management, AI insights trigger. It communicates with NestJS via
JWT-authenticated HTTPS calls. For sheet operations (writing data, reading data),
it goes through Apps Script as a bridge using google.script.run.

Google Apps Script Add-on (/addon)
The layer that lives inside Google Sheets. Handles the Extensions menu, sidebar
loading, reading data from sheet tabs, writing data to sheet tabs, creating and
naming tabs, applying formatting. Apps Script is the only layer that can directly
touch the Google Sheet the user has open. No npm packages — pure JavaScript only.
6-minute execution time limit per run.

Supabase (PostgreSQL via Prisma)
All persistent data. Users, encrypted Meta tokens, Google refresh tokens,
templates, schedules, AI reports. Prisma is the ORM — all DB access goes through
PrismaService. Never write raw SQL. Never access Supabase directly from sidebar
or Apps Script.

Google Sheets API (Backend)
Used exclusively by the NestJS scheduling engine to write data into user sheets
without the user being present. Requires the spreadsheets OAuth scope approved
by the user at first login. The Google refresh token is stored encrypted in
the ConnectedAccount table.

DATA FLOW SUMMARY
-----------------

Manual Import:
  Sidebar → NestJS /meta/import → Meta API → NestJS parses → returns rows
  → Sidebar receives rows → google.script.run.writeToSheet → Apps Script writes to sheet

Scheduled Import:
  NestJS cron fires → loads schedule from DB → calls Meta API
  → Google Sheets API writes to sheet directly

AI Insights:
  Sidebar → google.script.run.getSheetData → Apps Script reads sheet
  → Sidebar sends data to NestJS /ai/generate → NestJS calls OpenAI
  → Response returns to sidebar → google.script.run.writeToSheet → AI Insights tab written

RELATIONSHIPS:
- One User → many ConnectedAccounts (one per Meta ad account)
- One User → many Templates
- One User → many Schedules
- One Schedule → one Template + one ConnectedAccount
- One User → many AiReports
- onDelete: Cascade — deleting a user deletes all their data

5. AUTHENTICATION FLOW
================================================================================

GOOGLE OAUTH (Login + Sheets Scope — One Flow)
-----------------------------------------------
The user logs in with Google once. In this single OAuth flow, we request both the
login scopes AND the Google Sheets write scope. The user approves everything in
one screen. We store the Google refresh token encrypted for later Sheets writes.

SCOPES TO REQUEST:
  openid
  email
  profile
  https://www.googleapis.com/auth/spreadsheets

FLOW:
1.  Sidebar renders Login screen with Google Sign-In button
2.  User clicks → sidebar opens popup to GET /auth/google
3.  NestJS redirects to Google OAuth with all 4 scopes
    + prompt=consent&access_type=offline
    prompt=consent forces Google to return a refresh token every time
    access_type=offline is required to get the refresh token at all
4.  User approves → Google redirects to GET /auth/google/callback?code=...
5.  NestJS exchanges code for tokens via Google Token API
6.  NestJS receives access_token, refresh_token, id_token
7.  NestJS decodes id_token to get user email, name, googleId, avatarUrl
8.  NestJS upserts User row in DB (create if new, update if existing)
9.  NestJS encrypts refresh_token and stores in ConnectedAccount.googleRefToken
10. NestJS signs a JWT with { userId, email, plan } — expires in 30 days
11. NestJS returns JWT to sidebar
12. Sidebar stores JWT in PropertiesService.getUserProperties()

JWT STRUCTURE:
{
  "userId": "uuid",
  "email": "user@example.com",
  "plan": "free",
  "iat": 1234567890,
  "exp": 1234567890
}

All subsequent API calls:
  Authorization: Bearer <jwt>

JWT Guard in NestJS:
Every protected endpoint uses @UseGuards(JwtAuthGuard). The guard verifies the
JWT, extracts the payload, and attaches it to request.user.
Use @CurrentUser() decorator to access it in controllers.

6. META API INTEGRATION
================================================================================

6.1 Meta OAuth Flow (Connecting Ad Account)
--------------------------------------------
Separate from Google login. Connects the marketer's Meta Ads account.

SCOPES TO REQUEST:
  ads_read
  ads_management
  business_management
  read_insights

FLOW:
1.  Sidebar shows Connect Meta button
2.  User clicks → sidebar calls GET /meta/auth-url
3.  NestJS returns the Meta OAuth URL
4.  Sidebar opens popup to that URL
5.  User logs in with Facebook and approves permissions
6.  Meta redirects to GET /meta/callback?code=...
7.  NestJS exchanges code for short-lived token via:
    POST https://graph.facebook.com/oauth/access_token
8.  NestJS exchanges short-lived for long-lived token via:
    GET https://graph.facebook.com/oauth/access_token
        ?grant_type=fb_exchange_token&...
    Long-lived token lasts 60 days
9.  NestJS encrypts token with AES-256 and stores in ConnectedAccount.accessToken
10. NestJS stores tokenExpiresAt = now + 60 days
11. NestJS fetches Business Managers and Ad Accounts, returns to sidebar
12. Sidebar shows account selector


6.2 Token Encryption
---------------------
// src/common/crypto.util.ts
import * as CryptoJS from 'crypto-js';

const SECRET = process.env.ENCRYPTION_SECRET;

export const encrypt = (text: string): string =>
  CryptoJS.AES.encrypt(text, SECRET).toString();

export const decrypt = (cipher: string): string =>
  CryptoJS.AES.decrypt(cipher, SECRET).toString(CryptoJS.enc.Utf8);

Never store raw tokens. Always encrypt before saving, decrypt before using.


6.3 Token Refresh (Automated)
------------------------------
Runs daily at 2 AM via NestJS cron.
Finds tokens expiring within 7 days and refreshes them.

@Cron('0 2 * * *')
async refreshExpiringTokens() {
  const sevenDaysFromNow = new Date(Date.now() + 7 * 24 * 60 * 60 * 1000);
  const accounts = await this.prisma.connectedAccount.findMany({
    where: { tokenExpiresAt: { lte: sevenDaysFromNow } },
  });
  for (const account of accounts) {
    try {
      const rawToken = decrypt(account.accessToken);
      const { token, expiresAt } = await this.refreshMetaToken(rawToken);
      await this.prisma.connectedAccount.update({
        where: { id: account.id },
        data: { accessToken: encrypt(token), tokenExpiresAt: expiresAt },
      });
    } catch (err) {
      // Log failure — do not throw, continue to next account
    }
  }
}


6.4 Meta Insights API Call
---------------------------
Endpoint:
  GET https://graph.facebook.com/v18.0/{ad-account-id}/insights

Parameters built from template:

  fields          Built from template.metrics + template.dimensions
                  Always include: campaign_name, adset_name, ad_name, account_currency

  METRICS MAP:
    spend           → spend
    impressions     → impressions
    reach           → reach
    clicks          → clicks
    ctr             → ctr
    cpc             → cpc
    cpm             → cpm
    leads           → actions[action_type=lead]
    cpl             → cost_per_action_type[action_type=lead]
    roas            → purchase_roas
    frequency       → frequency
    thruplay        → video_thruplay_watched_actions
    vtr             → calculated: thruplay / impressions * 100
    cpv             → calculated: spend / thruplays

  time_range      { since: "YYYY-MM-DD", until: "YYYY-MM-DD" }
  level           campaign | adset | ad (from template.reportLevel)
  time_increment  1 for day, 7 for week, monthly for month
  filtering       JSON array from template.filters
  limit           500 (max per page)
  access_token    decrypt(account.accessToken)

FOR CREATIVE DATA (confirmed in v1):
  GET https://graph.facebook.com/v18.0/{ad-account-id}/ads
  ?fields=id,name,creative{title,body,image_url,thumbnail_url}
  &limit=500
  &access_token={token}
  Merge creative data onto ad-level rows by matching ad.id

PAGINATION:
  Meta returns max 500 rows per call. Always check data.paging.cursors.after.
  If present, make another call with &after={cursor} and append results.
  Repeat until no after cursor.

PERIOD COMPARISON:
  For every import, also fetch previous period with identical params.
  Calculate % change: ((current - previous) / previous) * 100
  Include current value, previous value, and % change in returned data.

9. SCHEDULING ENGINE
================================================================================

9.1 Architecture Decision
--------------------------
Scheduling is server-side in NestJS. NOT in Apps Script.

Apps Script time-based triggers are limited to 20 per user across all scripts.
A user with 15 clients at daily schedule hits 15 triggers immediately.
Server-side has no such constraint. This decision is final.


9.2 Cron Job
-------------
Runs every minute. Checks which schedules are due. Executes them.

@Cron('* * * * *')
async runDueSchedules() {
  const now = new Date();
  const due = await this.prisma.schedule.findMany({
    where: { status: 'active', nextRunAt: { lte: now } },
    include: { template: true, account: true, user: true },
  });
  await Promise.allSettled(due.map(s => this.executeSchedule(s)));
}


9.3 Execute Schedule
---------------------
async executeSchedule(schedule) {
  try {
    const data = await this.metaService.fetchForSchedule(schedule);
    await this.sheetsService.writeReport(schedule, data);
    await this.sheetsService.writeTimestamp(schedule);
    await this.prisma.schedule.update({
      where: { id: schedule.id },
      data: {
        lastRunAt: new Date(),
        lastRunStatus: 'success',
        lastError: null,
        retryCount: 0,
        nextRunAt: this.calculateNextRun(schedule),
      },
    });
  } catch (error) {
    await this.handleFailure(schedule, error);
  }
}


9.4 Failure and Retry
----------------------
Attempt 1 fails → set retryCount=1, nextRunAt = now + 15 minutes
Attempt 2 fails → set retryCount=2, nextRunAt = now + 30 minutes
Attempt 3 fails → set lastRunStatus='failed', lastError=message,
                   retryCount=0, nextRunAt = next scheduled occurrence
Sidebar shows:   "Auto-refresh failed on {date}. Click Retry Now."

9.6 Google Sheets API Write (Backend)
--------------------------------------
async writeReport(schedule: Schedule, data: ReportData) {
  const account = await this.prisma.connectedAccount.findFirst({
    where: { userId: schedule.userId },
  });

  const oauth2Client = new google.auth.OAuth2(
    process.env.GOOGLE_CLIENT_ID,
    process.env.GOOGLE_CLIENT_SECRET,
  );
  oauth2Client.setCredentials({ refresh_token: decrypt(account.googleRefToken) });

  const sheets = google.sheets({ version: 'v4', auth: oauth2Client });

  // values.update only updates content — preserves cell formatting
  await sheets.spreadsheets.values.update({
    spreadsheetId: schedule.sheetId,
    range: `${schedule.sheetTabName}!A1`,
    valueInputOption: 'RAW',
    requestBody: { values: [data.headers, ...data.rows] },
  });
}

----------------------
The AI does NOT run automatically. Marketer clicks button when ready.

1.  User clicks Generate AI Insights in sidebar
2.  Sidebar calls google.script.run.getSheetData({ accountName })
3.  Apps Script reads data from Campaigns, Ad Sets, Ads tabs

function writeToSheet(payload) {
  // payload: { tabName, headers, rows, dateRange, accountName }
  const ss = SpreadsheetApp.getActiveSpreadsheet();
  let sheet = ss.getSheetByName(payload.tabName);
  if (!sheet) sheet = ss.insertSheet(payload.tabName);
  sheet.clearContents();

  // Row 1: metadata
  sheet.getRange(1, 1).setValue(
    payload.accountName + ' | ' + payload.dateRange +
    ' | Imported: ' + new Date().toLocaleString('en-IN')
  );

  // Row 2: headers (bold)
  sheet.getRange(2, 1, 1, payload.headers.length).setValues([payload.headers]);
  sheet.getRange(2, 1, 1, payload.headers.length).setFontWeight('bold');

  // Row 3+: data rows
  if (payload.rows.length > 0) {
    sheet.getRange(3, 1, payload.rows.length, payload.rows[0].length)
      .setValues(payload.rows);
  }

  // Auto-resize columns
  for (let i = 1; i <= payload.headers.length; i++) {
    sheet.autoResizeColumn(i);
  }

  return { success: true, rowsWritten: payload.rows.length };
}

function writeAiInsights(payload) {
  // payload: { tabName, accountName, dateRange, timestamp, content }
  const ss = SpreadsheetApp.getActiveSpreadsheet();
  let sheet = ss.getSheetByName(payload.tabName);
  if (!sheet) sheet = ss.insertSheet(payload.tabName);
  sheet.clearContents();

  const rows = [
    [payload.accountName + ' — AI Insights'],
    ['Period: ' + payload.dateRange + ' | Generated: ' + payload.timestamp],
    [''],
    ...payload.content.map(line => [line]),
    [''],
    ['-- Your notes (add below before sending to client) --'],
    [''], [''], [''],
  ];

  sheet.getRange(1, 1, rows.length, 1).setValues(rows);
  sheet.getRange(1, 1).setFontWeight('bold').setFontSize(12);

  const headings = [
    'PERFORMANCE SUMMARY',
    'CREATIVE FATIGUE ALERT',
    'BUDGET WASTE ALERT',
    'SCALING OPPORTUNITY'
  ];
  for (let i = 1; i <= rows.length; i++) {
    if (headings.includes(sheet.getRange(i, 1).getValue())) {
      sheet.getRange(i, 1).setFontWeight('bold');
    }
  }

  sheet.autoResizeColumn(1);
  return { success: true };
}

function getSheetData(payload) {
  // payload: { accountName }
  const ss = SpreadsheetApp.getActiveSpreadsheet();
  const levels = ['Campaigns', 'Ad Sets', 'Ads'];
  const result = {};
  for (const level of levels) {
    const tabName = payload.accountName + ' — ' + level;
    const sheet = ss.getSheetByName(tabName);
    if (sheet) {
      const data = sheet.getDataRange().getValues();
      result[level.toLowerCase().replace(' ', '_')] = {
        headers: data[1] || [],   // row 2 is headers
        rows: data.slice(2) || [] // data starts at row 3
      };
    }
  }
  return result;
}

function getSpreadsheetId() {
  return SpreadsheetApp.getActiveSpreadsheet().getId();
}

  return {

    url: ss.getUrl(),
    sheets: ss.getSheets().map(s => s.getName()),
  };
}

// src/utils/appscript.ts
export const runScript = <T>(fnName: string, payload?: any): Promise<T> => {
  return new Promise((resolve, reject) => {
    (window as any).google.script.run
      .withSuccessHandler(resolve)
      .withFailureHandler(reject)
      [fnName](payload);
  });
};

// Usage:
const data = await runScript<SheetData>('getSheetData', { accountName: 'Pushpak Ads' });
await runScript('writeToSheet', { tabName: '...', headers: [...], rows: [...] });

15. EDGE CASES — FULL LIST
================================================================================

META API
--------
Rate limit (code 17 or 613)
  Catch, wait 60 seconds, retry once, return 429 to sidebar if still failing.

Pagination
  Always loop through all pages using cursor. Never return partial data.

Empty date range
  Campaign exists but no spend. Return empty rows array, not an error.

Different currency per account
  Always include account currency field in every row.

Account deactivated (code 100)
  Show: "This ad account is inactive or has been deactivated."

Token revoked by user from Meta (code 190)
  Prompt reconnect immediately.

Business Manager access removed (code 200)
  Show which BM lost access.

IMPORT
------
Tab already exists
  Overwrite from row 1. Do not append.

Sheet deleted by user
  Catch 404 from Sheets API. Show error in sidebar.

Over 1000 rows
  Warn: "This report has {n} rows and may take a moment."

Column order has unknown field
  Skip that field silently. Do not error.

Scheduled refresh while user is editing
  values.update only touches the data range. User's edits outside are preserved.

TEMPLATES
---------
Delete template with active schedules
  Block delete. Show: "This template is used by {n} active schedules.
  Delete the schedules first."

Edit template with active schedules
  Allow edit. Note: "Changes apply to all schedules using this template
  from the next run."

SCHEDULES
---------
Schedule fires while Meta API is down
  Retry mechanism handles it. Mark failed after 3 attempts.

Google Sheet deleted
  Sheets API returns 404. Mark schedule as failed with clear error.

Google refresh token expired
  Re-authentication prompt.

Two schedules for same account at same time
  Both run. Both write to different tabs. No conflict.

Timezone DST changes
  date-fns-tz handles this automatically.

AI INSIGHTS
-----------
Empty sheet
  Show: "Import your campaign data first."

Low spend (under Rs. 500 total)
  Add caveat to prompt: "Note: spend is very low. Insights may be limited."

OpenAI timeout
  30-second timeout on axios call. Catch and return 500 with user message.

GPT-4 output does not follow 4-section format
  Parse defensively. Fall back to showing raw output if parsing fails.

Stale data warning
  If last import was more than 24 hours ago: "Your data was last imported
  {time ago}. Import fresh data for accurate insights."

AUTH
----
JWT expired
  401 response. Sidebar catches globally, clears token, redirects to login.

Two browsers simultaneously
  Both JWTs valid. Both work independently.

Google access revoked by user
  Detect on next Sheets write. Prompt user to log in again.
